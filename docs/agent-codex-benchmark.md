# 内置 Agent：Codex 对照与演进顺序

> 2026-10-23 对照 [openai/codex](https://github.com/openai/codex)、[Codex app 介绍](https://openai.com/index/introducing-the-codex-app/)和[工程实践指南](https://developers.openai.com/blog/mastering-codex-remote-for-engineering)。这是产品能力与交互原则的参考，不把桌面 App 界面误认为该开源仓库的全部源码。

## 应学习的工作方式

Codex 将“提任务 → 看过程 → 审阅改动 → 继续指挥”做成连续流程。内置 Agent 也应围绕这个流程组织：工作区是会话上下文，工具调用有状态，写入有可审阅边界，完成后留下可继续工作的记录。UI 采用清晰的任务入口、克制的层级、就地展开的活动记录、明确的批准界面，沿用本插件现有的浅深色、宿主强调色与玻璃 token。

| 能力 | 现状 | 下一步 |
|---|---|---|
| 多会话与工作区 | 已按工作区分组并恢复会话配置 | 在会话顶部展示当前工作区和最近变更概览 |
| 工具调用与停止 | 已有流式工具状态、权限分档和停止信号；本轮补齐命令停止 | 把取消、失败和部分完成统一纳入回执与会话记录 |
| 执行记录 | 保存工具名与最终状态，可在历史消息内折叠查看 | 按阶段分组，支持定位失败步骤与重试建议 |
| 写入前审阅 | 基于文件现状展示行差异、完整拟写入内容与命令参数；批准期间文件变化会拒绝写入 | 在大文件上优化差异分块与性能 |
| 完成后审阅 | 展示已回读验证的修改文件，失败或中止后也保留 | 加入测试结果、文件打开和安全撤销 |
| 计划与引导 | Agent 可发布、更新最多 8 步计划，并在本地会话中查看 | 支持用户直接修改步骤 |
| 排队与中途指挥 | 可在当前侧栏内排队最多 5 条后续纯文本指令；正常完成自动接续，中止后手动继续，关闭侧栏清空队列 | 支持在工具边界安全地修改当前任务 |
| 隔离工作 | 可从当前仓库已提交的 `HEAD` 主动创建 detached worktree 并切换；原目录未提交改动不复制，隔离目录不自动删除 | 增加工作树列表、变更审阅与清理入口 |
| 可复用能力 | 当前是固定工具注册表 | 引入可审阅的本地任务模板/技能，明确适用范围与权限 |
| 自动化与并行任务 | 现有定时任务系统与 Agent 尚未直接编排 | 先做单任务可靠恢复，再接计划触发、并行与资源限额 |

## 实施顺序

1. **已完成：可监督的单任务流程。** 任务入口、历史活动、写入预览、停止，以及有界的本地历史元数据。
2. **已完成核心：可复核的文件结果。** 基于写入前文件快照展示行差异；批准后若文件变化则拒绝写入；写入后回读并汇总验证过的相对路径。测试结果与撤销仍需单独设计。
3. **已完成核心：可指挥的长任务。** 计划、后续消息队列、停止边界；运行中的任务不接受直接改写模型上下文，停止后由用户手动继续队列。跨应用重启恢复未完成任务仍需设计。
4. **隔离已具备基础入口；复用仍待后续。** 用户可创建 Git worktree 并切换 Agent 工作区。模板/技能、自动化、并行任务以及 worktree 清理，仍依赖更完整的任务恢复与资源管理机制。

## 验收原则

- 用户在批准前能看清目标、完整拟写入内容与命令参数；批准后实际执行的内容应与审阅内容一致。
- 停止命令后不得再派发后续工具；写入成功以回读结果为准，未验证时明确告知。
- 历史记录能回答“调用了哪些工具、结果如何”，但不额外落盘工具参数、输出或附件。
- 窄侧栏、浅深色、键盘焦点和低动效设置都可用；构建与测试通过之后还需宿主实测。
